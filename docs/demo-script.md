# SPECTRUM 演示脚本

## 一、推荐演示时长

建议控制在 5～7 分钟。先讲问题和价值，再演示完整链路，最后讲技术架构。

## 二、开场（30 秒）

> 很多个人创业者、小微商家和独立创作者并不缺内容工具，真正缺的是一套持续一致
> 的品牌系统。SPECTRUM 用智能体把品牌定位、视觉规范、Logo 和多平台营销物料
> 串成一条可追踪、可恢复的生产流程。

## 三、产品演示（3～4 分钟）

### 1. 创建品牌

选择“个人品牌”“店铺品牌”或“产品品牌”，说明三个入口复用同一套智能体架构，
只是提问策略和平台选项不同。

宠物店故事线可以依次输入：

1. 宠物店
2. 爱宠
3. 高端商场里的宠物 SPA
4. 活力俏皮

重点说明：

- 用户消息先显示，再由智能体判断下一步
- 用户可以随时提问、纠错或改变方向
- 风格确定后才建立色彩和排版体系

### 2. 生成 Logo

选择 Logo 方向，例如“字母标与抽象符号结合”。

重点说明：

- Logo 会成为后续物料的参考资产
- 失败时保留上下文，可直接重试
- 没有真实生成成功时，系统不会伪造完成状态

### 3. 生成多平台资产

依次演示：

- 美团店铺主页：可爱的宠物特写
- 美团服务：专属皮毛调理洗护 168 元
- 小红书主页：体现店铺特色
- 小红书海报：推广店铺
- 微信主页和朋友圈推广物料

每完成一个资产，指出三个同步结果：

1. 对话区返回任务结果
2. 品牌资产库新增可下载原图
3. 对应平台模拟界面更新

### 4. 展示品牌知识库

展开品牌资产，点击右上角“＋”，上传一份品牌规范 TXT 或 PDF。

检索示例：

> Logo 可以变形吗？

展示检索片段、相关度和引用来源，说明智能体后续生成前会自动读取这些规范，而不是
只依赖一段固定 Prompt。

## 四、技术讲解（1～2 分钟）

> 前端使用 React、Next.js 和 TypeScript；交互层由 LangGraph.js 管理。Python
> 服务使用 FastAPI、Pydantic 和 LangGraph，负责高级路由、RAG 与持久化。
> PostgreSQL 保存品牌、会话、资产、知识片段和 Trace；Redis保存短期状态与任务
> 进度；图片和文档进入 S3 兼容对象存储。

继续说明：

- RAG 覆盖文档解析、混合召回、Rerank、引用和 Recall@K/MRR 评测
- Python 服务不可用时，前端自动回退到 TypeScript 智能体
- 质量门检查品牌一致性、资产落库和预览同步
- 测试覆盖智能体路由、RAG、API、对象存储回退和生产构建

## 五、收尾（30 秒）

> SPECTRUM 验证的不是“能不能生成一张图”，而是 AI 能否持续理解品牌、调用工具、
> 管理状态，并把不同平台的内容生产组织成一套可靠的业务流程。下一阶段可以加入团队
> 协作、品牌版本管理、专业视觉审核和更多平台发布接口。

## 六、常见追问

### 这是真智能体还是固定流程？

系统保留品牌阶段作为业务约束，但每条消息先经过路由判断。提问、纠错、重试、平台
切换和生成任务会进入不同节点，不会全部按固定表单推进。

### 为什么同时有 TypeScript 和 Python？

TypeScript 靠近交互与前端状态，Python 承担 AI 后端、RAG 和数据服务。双运行时也
提供了降级能力，Python 暂时不可用时不会导致整个演示中断。

### 如何保证品牌一致？

视觉令牌、Logo、定位和知识库引用会进入生成上下文；生成后再经过质量门，并同步到
统一资产库和平台预览。

### 当前完成度如何？

本地 MVP 已完成并通过测试；前端有在线演示。线上 Python、PostgreSQL 和 Redis
尚未部署，因此线上知识库能力暂不可用。
